# Hospital Infection Control — Complex Systems and Applications Final Project

**Option 1** of the LEAP Complex Systems and Applications final project, followed through Aristotle's University of Thessaloniki E-learning platform. This repository contains one completed, run-to-completion Jupyter notebook that acts as both the deliverable and the portfolio item, as required by the course.

## 1. Problem statement

A regional hospital group records patient transfers between wards. At an observation point, 18 of 120 wards already have an active infection cluster; the rest are eligible for a new, simulated cluster over the following 14 days.

**Central question:** do earlier, directed ward-to-ward transfers add predictive information about a later cluster, beyond two static ward attributes (bed occupancy ratio and invasive-device use)?

The project deliberately stops short of an operational claim: it asks whether a fair, like-for-like model comparison shows a measurable difference on this one synthetic sample — not whether transfers *cause* infection spread.

## 2. Data set

Two prepared, synthetic CSV files (constructed by course staff, not generated by this notebook):

| File | Rows | Fields |
|---|---|---|
| `hospital_wards.csv` | 120 wards | `ward_id`, `occupancy_ratio`, `device_use_share`, `active_cluster_at_start`, `new_cluster_later` (blank for the 18 wards already affected) |
| `hospital_transfers.csv` | 420 directed links | `source_ward_id`, `destination_ward_id`, `transfer_count` |

The notebook fetches both files from the course URL at runtime and falls back to local copies beside the notebook if the URL is unreachable. Both files are included in this repository for offline reproducibility. See `Synthetic_Hospital_Data_Construction.pdf` for the full generation rule (this is provided for transparency only — the notebook does not reproduce it, and synthetic results are not evidence about real hospitals).

## 3. Method

1. **EDA** — restrict to the 102 eligible wards (no active cluster at the observation point), count later-outcome classes, and compare `occupancy_ratio` / `device_use_share` between the two outcome groups.
2. **Network construction** — build a directed graph (wards = nodes, transfers = weighted edges) from `hospital_transfers.csv`, including isolated wards. Derive two features per ward, using only information available at the observation point:
   - `incoming_volume`: total weighted in-degree (all incoming transfers).
   - `from_active_volume`: incoming transfer volume received specifically from wards with `active_cluster_at_start == 1`.
3. **Modelling** — one stratified train/test split of the 102 eligible wards (30 held out for testing, `random_state=123`). Two logistic regression pipelines (`StandardScaler` fit on training rows only → `LogisticRegression`), fit and evaluated on the identical split:
   - **Model A (baseline):** `occupancy_ratio`, `device_use_share`.
   - **Model B (network):** Model A's features plus `incoming_volume`, `from_active_volume`.
4. **Evaluation** — accuracy, F1 (for the later-cluster class), ROC AUC (from predicted probabilities), and a confusion matrix for each model.

## 4. Results

| Model | Accuracy | F1 | ROC AUC |
|---|---|---|---|
| Original ward features | 0.600 | 0.455 | 0.703 |
| Ward + network features | 0.867 | 0.778 | 0.895 |

On this test split, adding the two network features improved every metric. The confusion matrices show the gain came mainly from eliminating false positives (6 → 0) and reducing false negatives (6 → 4).

Full plots (EDA bar/box charts, the network illustration, the exposure histogram, and both confusion matrices) are in the notebook with outputs already rendered — see `Option1_Hospital_Infection_Control.ipynb`.

## 5. Interpretation and limitations

- This is a single fixed synthetic sample (120 wards, 420 transfers) with an arbitrary, staff-authored probability rule behind the later label — the result is not evidence that ward-transfer network position predicts real infection clusters, and the score gain does not establish that transfers caused clusters.
- A recorded transfer link is not a validated infection-transmission route; no clinical, pathogen, or contact-tracing data is present.
- A model score change on one held-out split of 30 wards is not sufficient grounds to guide real clinical or infection-control decisions.
- If a model like this were ever used to prioritise attention, a false alarm (unnecessary isolation, wasted staff time) and a missed cluster (undetected transmission) carry very different costs — flagged wards should be reviewed by infection-control clinicians before any action, not acted on automatically.

## 6. Reflection

What worked well: the directed-graph feature engineering (`incoming_volume`, `from_active_volume`) was straightforward with `networkx`, and fitting the scaler inside a pipeline made the "scale on training data only" requirement easy to satisfy correctly. What was difficult: keeping the two models perfectly comparable (same split, same eligible rows) required care, since it's easy to accidentally leak the network features into the EDA-stage plots. With more time, the comparison would benefit from repeating the split with several random seeds (or cross-validation) to see how much the reported metric gap is an artefact of one particular 30-ward test set, since the current numbers rest on a single split.

## 8. How to clone and run end-to-end

```bash
# 1. Clone the repository
git clone <your-repository-url>
cd CS_LEAP

# 2. Create and activate a virtual environment
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Launch Jupyter and open the notebook
jupyter lab Option1_Hospital_Infection_Control.ipynb
# then Run > Run All Cells

# Alternatively, execute it headlessly end-to-end from the command line:
jupyter nbconvert --to notebook --execute --inplace Option1_Hospital_Infection_Control.ipynb
```

No internet connection is required: the notebook first tries the course URL, and automatically falls back to the `hospital_wards.csv` / `hospital_transfers.csv` copies included in this repository.
